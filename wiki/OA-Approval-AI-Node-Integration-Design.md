# OA 审批 AI 节点接入设计

> 文档定位：在现有 OA 审批流中插入 AI 辅助节点的接入设计说明书  
> 关联文档：[企业级 AI 中台能力域模型与 react-ai 差距分析](AI-Middle-Platform-Gap-Analysis.md)  
> 设计原则：**AI 只做预审、摘要、风险提示与建议，最终决策权始终属于人**

---

## 1. 目标与范围

### 1.1 目标

1. 在审批链的关键位置插入 AI 节点，降低人工阅读、核对、退回返工的成本。
2. 让每条 AI 结论可解释、可追溯：有证据引用、有置信度、有版本号。
3. 接入 AI 中台统一能力（模型网关、知识检索、护栏、审计、指标），避免 OA 侧重复建设。
4. 支持多租户、多组织、多单据类型的差异化配置与灰度。

### 1.2 范围

| 范围内 | 范围外 |
|---|---|
| 审批链上的预审、摘要、风险提示、会签汇总、归档质检 | 替代人工做最终审批决策 |
| AI 建议的接口契约、幂等、超时降级、审计 | 重构 OA 流程引擎本身 |
| 租户/用户/角色/配额模型 | OA 组织主数据的建设（由 OA/IAM 负责） |
| POC 度量指标与实验设计 | 具体模型微调与训练 |

### 1.3 设计原则

1. **人机协同**：AI 输出「建议 + 证据 + 置信度」，不直接改变审批状态。
2. **硬规则前置**：金额阈值、黑名单、预算余额、重复报销等确定性规则不交给大模型。
3. **可解释**：每条风险与建议必须绑定单据字段、附件位置或制度条款。
4. **失败不阻断**：AI 超时、限流、模型不可用时，审批流按原路径继续。
5. **最小权限**：AI 只能读审批所需数据，写操作必须走 HITL 审批。
6. **可灰度可回滚**：按租户/部门/单据类型/金额档位灰度，模型与提示词版本可回滚。

## 2. 总体架构

```text
+---------------------------------------------------------------+
|                         OA 审批系统                            |
|  表单引擎 | 流程引擎 | 审批人解析 | 消息通知 | 审批工作台        |
+----------------------------+----------------------------------+
                             | 事件 / 同步查询（内网 + mTLS）
                             v
+---------------------------------------------------------------+
|                    AI 中台接入网关                             |
|  JWT 校验 | 租户身份注入 | 配额限流 | 幂等 | 路由              |
+----------------------------+----------------------------------+
                             |
                             v
+---------------------------------------------------------------+
|                    AI 审批编排层                               |
|  硬规则引擎 -> 附件抽取 -> 知识检索 -> 模型判断 -> 护栏 -> 闸门  |
+------+----------------+----------------+----------------+------+
       |                |                |                |
       v                v                v                v
   工具层           知识/记忆层        模型网关        安全与运营
 单据/预算/      制度库/历史案例    多模型路由     护栏/审计/
 发票/黑名单      /用户偏好         容灾降级       指标/成本
```

### 2.1 部署边界

- OA 与 AI 中台通过内网网关通信，启用 mTLS 或双向 API Key。
- 异步任务走消息队列（Kafka/RocketMQ），保证至少一次投递 + 幂等消费。
- AI 侧不直连 OA 数据库，只通过 OA 提供的只读业务接口取数。
- 所有请求携带 `trace_id`，在 OA 与中台日志中串联。

## 3. 流程节点图

### 3.1 主流程与 AI 节点位置

```text
[发起人提交]
      |
      v
[单据校验节点] --失败--> [退回发起人：补齐材料]
      |
      | 成功
      v
+-------------------------------------------------------+
| AI 预审节点（异步旁路，不阻塞主流程）                    |
|  硬规则 -> 附件抽取 -> 制度/案例检索 -> 模型判断         |
|  -> 护栏 -> 置信度闸门 -> 建议卡片回写                   |
+-------------------------------------------------------+
      |
      | 建议卡片（只读，不改变审批状态）
      v
[直属主管审批] <---- AI 助手：摘要 / 风险 / 条款引用
      |
      +--驳回--> [退回发起人]
      |
      | 通过
      v
[金额/类型判断]
      |                         |
      | 低于阈值                 | 高于阈值
      v                         v
[财务复核]                 [财务经理会签] <---- AI 会签汇总
      |                         |
      +------------+------------+
                   |
                   v
[审批人终审]（人工决策，AI 不自动放行）
                   |
          +--------+--------+
          |                 |
       驳回               通过
          |                 |
          v                 v
   [退回发起人]         [归档]
                            |
                            v
                 [归档后 AI 质检（抽样）]
                            |
                            v
                    [badcase 回流与评测]
```

### 3.2 节点职责

| 节点 | 触发方式 | AI 输入 | AI 输出 | 失败/超时处理 |
|---|---|---|---|---|
| 预审 | 单据提交事件（异步） | 单据字段、附件、制度范围 | 缺失项、一致性问题、风险标签、预审结论 | 记录降级，主流程照常进入审批 |
| 审批人助手 | 审批人打开单据（同步读缓存） | 单据、附件摘要、历史相似案例 | 摘要、风险点、条款引用、建议与置信度 | 展示「AI 建议暂不可用」，人工照常审批 |
| 会签汇总 | 会签节点激活（异步） | 各会签人意见、单据 | 分歧项、待决议清单、汇总摘要 | 退回人工汇总 |
| 归档质检 | 归档事件（异步抽样） | 全流程记录、审批意见 | 合规问题、越权/拆单线索 | 进入人工复核队列 |
| 流程运营 | 定时任务 | 流程事件与耗时 | 瓶颈节点、积压预警、SLA 预测 | 仅影响看板，不影响业务 |

### 3.3 插入方式选择

| 方式 | 适用节点 | 优点 | 代价 |
|---|---|---|---|
| 异步旁路（推荐） | 预审、会签汇总、归档质检 | 不阻塞流程，可重试 | 结果回写有延迟 |
| 同步只读 | 审批人助手 | 即时展示 | 受超时与配额约束 |
| 人工触发 | 高风险单据二次复核 | 成本可控，便于灰度 | 依赖审批人主动使用 |

> 建议：**先做审批人助手（只读、可关闭）**，验证建议采纳率后再上预审与自动质检。

## 4. 接口契约

### 4.1 通用约定

| 项 | 约定 |
|---|---|
| Base URL | `POST /api/v1/ai/approval/reviews` |
| 鉴权 | `Authorization: Bearer <JWT>`；`tenant_id`、`user_id`、`roles` 从 JWT 声明中解析，**禁止请求体传入身份** |
| 幂等 | `Idempotency-Key: {bill_id}:{node_id}:{bill_version}:{review_mode}` |
| 追踪 | `X-Trace-Id` 透传；未传时由网关生成 |
| 超时 | 同步模式超时阈值可配置（建议 3–8 秒）；超时返回降级结果 |
| 版本 | 模型、提示词、知识库、规则集均返回版本号，便于回放 |

### 4.2 请求

```json
{
  "review_mode": "precheck",
  "bill": {
    "bill_type": "expense_reimbursement",
    "bill_id": "BX20261109001",
    "bill_version": 3,
    "node_id": "manager_approve",
    "amount": 12800,
    "currency": "CNY",
    "department_id": "D_SALES_01",
    "applicant_id": "U1001",
    "submitted_at": "2026-11-09T10:20:00+08:00",
    "fields": {
      "expense_type": "travel",
      "budget_code": "BUDGET-2026-Q4-SALES"
    }
  },
  "attachments": [
    {
      "file_id": "F001",
      "name": "invoice_01.pdf",
      "mime": "application/pdf",
      "url": "https://oa-internal/files/F001",
      "sha256": "9f2c..."
    }
  ],
  "policy_scope": ["finance", "reimbursement"],
  "locale": "zh-CN",
  "options": {
    "need_summary": true,
    "need_citations": true,
    "max_findings": 10
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `review_mode` | 是 | `precheck` / `assist` / `consensus` / `postcheck` |
| `bill.bill_type` | 是 | 单据类型，用于选择提示词、规则集与知识范围 |
| `bill.bill_id` | 是 | 业务主键，用于幂等与审计 |
| `bill.bill_version` | 是 | 单据版本，版本变化才重新计算 |
| `bill.node_id` | 是 | 审批节点，决定 AI 的职责边界 |
| `bill.fields` | 是 | 脱敏后的业务字段，禁止传无关个人信息 |
| `attachments` | 否 | 只传引用与哈希，不传文件内容 |
| `policy_scope` | 否 | 允许检索的制度域，默认按租户配置 |
| `options` | 否 | 输出裁剪选项 |

### 4.4 状态与错误码

| HTTP | code | 含义 | OA 侧处理 |
|---|---|---|---|
| 200 | `completed` | 建议生成成功 | 展示建议卡片 |
| 202 | `queued` | 异步任务已受理 | 轮询或等待回调 |
| 200 | `degraded` | 降级完成（如无知识命中） | 展示有限建议并标注 |
| 400 | `invalid_payload` | 参数不合法 | 记录并跳过 AI |
| 401 | `unauthorized` | 凭证无效 | 不重试，告警 |
| 403 | `tenant_mismatch` | 跨租户访问 | 记录安全事件 |
| 409 | `duplicate` | 幂等键命中 | 返回原结果，不重复计费 |
| 422 | `schema_validation_failed` | 模型结构化输出校验失败 | 降级为人工 |
| 429 | `quota_exceeded` | 租户配额耗尽 | 降级为人工，通知租户管理员 |
| 503 | `model_unavailable` | 全部模型节点失败 | 降级为人工 |
| 504 | `ai_timeout` | 同步超时 | 降级为人工，异步补算可选 |

### 4.5 异步回写（可选）

```json
// AI 中台 -> OA
POST /oa/internal/ai-review-results
{
  "bill_id": "BX20261109001",
  "bill_version": 3,
  "node_id": "precheck",
  "review_id": "RV202611090001",
  "status": "completed",
  "result_uri": "/api/v1/ai/approval/reviews/RV202611090001",
  "trace_id": "trace-xxx"
}
```

OA 收到回写后仅刷新建议卡片，不改变审批状态；回写失败进入重试队列，不阻塞主流程。

## 5. AI 节点内部执行链路

```text
1. 鉴权与上下文装配
   校验 JWT -> 注入 tenant/user/roles -> 读取租户配置 -> 幂等占位
2. 硬规则判定（不调用模型）
   金额阈值 / 预算余额 / 黑名单 / 重复报销 / 必填材料 / 时间窗口
3. 结构化抽取
   附件 OCR、发票验真、字段对齐、缺失项识别
4. 知识检索
   制度条款、历史相似案例、部门特殊规则；按租户与权限过滤
5. 模型判断
   结构化输出：结论 + 风险项 + 证据引用 + 置信度
6. 护栏与闸门
   输入注入检测 / PII 脱敏 / 输出合规审核 / 置信度阈值
7. 回写与审计
   建议卡片、版本号、trace_id、审计记录、指标上报
```

### 5.1 决策规则

| 条件 | 输出 |
|---|---|
| 硬规则命中阻断项 | `decision=reject` 或 `supplement`，模型不参与该条结论 |
| 模型结论与硬规则冲突 | 以硬规则为准，记录冲突事件供复盘 |
| 置信度 ≥ 高阈值且证据完整 | 给出明确建议 |
| 置信度处于中低区间 | 只给「需人工确认」与待核项，不给通过/驳回 |
| 关键数据缺失（附件无法解析等） | `status=degraded`，列为缺失项 |
| 全部模型失败 / 超时 | `status=degraded`，OA 侧转人工 |

### 5.2 版本与灰度

- 提示词通过 `PromptManager` 版本化，按 `trace_id` 稳定灰度（[prompts/manager.py](file:///d:/code/react-ai/src/react_ai/prompts/manager.py)）。
- 模型路由按租户配置选择主备模型，失败自动降级（[llm/router.py](file:///d:/code/react-ai/src/react_ai/llm/router.py)）。
- 知识库按租户与制度域隔离，检索结果强制带版本与条款号。
- 每次响应返回 `versions`，审计可回放到具体模型/提示词/知识版本。

## 6. 租户模型

### 6.1 实体关系

```text
Tenant（集团/公司，隔离主键）
  ├── TenantConfig（模型、配额、知识范围、护栏策略、留存期）
  ├── OrgUnit（部门/组织树，支持多级）
  ├── UserMapping（OA 用户 ↔ 平台身份，租户内唯一）
  ├── RoleAssignment（平台角色 / 租户角色 / 业务角色）
  ├── KnowledgeSpace（制度库、案例库，按部门授权）
  └── Quota（月度 token、并发、调用次数、成本预算）
```

### 6.2 核心字段

| 实体 | 关键字段 |
|---|---|
| `Tenant` | `tenant_id`、名称、状态、套餐、创建时间 |
| `TenantConfig` | 可用模型、`qps_limit`、`token_quota`、`cost_budget`、知识空间、`prompt_channel`、`guardrail_profile`、`approval_thresholds`、`data_retention_days` |
| `OrgUnit` | `org_id`、`tenant_id`、`parent_id`、`path`、类型 |
| `UserMapping` | `platform_user_id`、`tenant_id`、`external_user_id`、显示名、状态、所属组织 |
| `RoleAssignment` | 主体、角色、作用域（平台/租户/部门）、有效期 |
| `Quota` | 维度（租户/部门/用户）、周期、已用量、上限 |

### 6.3 身份与角色

- **身份事实源**：OA/IAM 为唯一事实源；中台只做映射，不维护用户主数据。
- **身份传递**：SSO/OIDC → JWT；网关校验签名并把 `tenant_id/user_id/roles/scopes` 注入上下文，禁止客户端自报。
- **角色分层**：

| 层级 | 角色 | 权限 |
|---|---|---|
| 平台 | 超级管理员 | 租户开通、全局策略、跨租户运维（需审计） |
| 平台 | 审计员 | 只读审计、合规抽查 |
| 租户 | 租户管理员 | 配额分配、知识空间、提示词灰度、查看本租户指标 |
| 租户 | 知识管理员 | 制度库维护、发布与回滚 |
| 业务 | 审批人 | 查看 AI 建议、做最终决策、反馈建议质量 |
| 业务 | 发起人 | 提交单据、查看预审结果、补齐材料 |

> 职责分离：AI 建议的配置者不得成为该单据的最终审批人；发起人不得自批。

### 6.4 权限矩阵（示例）

| 操作 | 平台管理员 | 租户管理员 | 知识管理员 | 审批人 | 发起人 | 审计员 |
|---|---|---|---|---|---|---|
| 开通/停用租户 | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| 分配配额 | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| 维护制度库 | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |
| 调整提示词灰度 | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| 查看 AI 建议 | ✅（审计用途） | ✅ | ❌ | ✅ | ✅（仅本人单据） | ✅（只读） |
| 最终审批 | ❌ | ❌ | ❌ | ✅ | ❌ | ❌ |
| 导出审计报告 | ✅ | ✅ | ❌ | ❌ | ❌ | ✅ |

### 6.5 隔离实现

| 层面 | 措施 |
|---|---|
| 身份 | JWT 签名 + 租户声明校验；跨租户请求返回 403 |
| 存储 | 所有业务表带 `tenant_id`；应用层硬闸 + 数据库行级安全（RLS） |
| 向量库 | 检索 SQL 强制 `tenant_id` / `user_id` 过滤（参考 [pgvector.py#L138-L143](file:///d:/code/react-ai/src/react_ai/memory/vector/pgvector.py#L138-L143)） |
| 对象存储 | 路径前缀 `tenant/{tenant_id}/`，签名 URL 短时效 |
| 缓存 | 键前缀 `t:{tenant_id}:...`，禁止跨租户复用 |
| 审计与指标 | 按租户维度归集，平台侧仅聚合脱敏数据 |
| 配额 | 按租户独立计量，超限返回 429 或降级 |

### 6.6 生命周期

| 阶段 | 动作 |
|---|---|
| 开通 | 创建租户、绑定 OA 组织、初始化配额与知识空间、分配管理员 |
| 变更 | 组织调整同步映射；角色变更即时生效；配额调整留审计 |
| 离职 | 禁用账号、回收权限与配额、按策略转移待办 |
| 数据删除 | 长期记忆 `forget_user`、会话与工具结果 `clear_user`；审计按留存策略保留并证明删除 |
| 租户停用 | 全量停用账号、导出数据、按合同清理存储 |

## 7. 安全与合规

| 风险 | 措施 |
|---|---|
| 身份伪造/越权 | 网关注入身份、禁止请求体覆盖、审批接口校验审批人角色与租户 |
| 提示词注入 | 用户字段与附件文本进入模型前做注入检测，命中即阻断并审计 |
| PII 泄露 | 输入脱敏、输出脱敏、日志字段白名单；附件只传引用不传正文 |
| 模型幻觉 | 结构化输出校验、证据引用强制、低置信转人工、冲突以硬规则为准 |
| 数据越权检索 | 知识空间按租户/部门授权，检索结果带权限校验 |
| 审计缺失 | 每次 AI 调用记录 who/when/what/versions/result/trace_id |
| 成本失控 | 租户配额、按单据类型限流、缓存、低成本模型降级 |

## 9. POC 度量方案

### 9.1 假设与目标

| 编号 | 假设 | 验证指标 |
|---|---|---|
| H1 | AI 建议能减少审批人阅读与核对时间 | 单均审批时长下降 |
| H2 | AI 预审能减少材料缺失导致的退回 | 退回率下降、一次通过率提升 |
| H3 | AI 建议具备可采纳性 | 建议采纳率、采纳后人工修改率 |
| H4 | 风险识别精度可接受 | 风险准确率、漏检率 |
| H5 | 成本可控 | 单均 AI 成本、降级率 |

**不预设百分比收益**：先测基线，再与同期对照组比较，用数据决定是否扩大范围。

### 9.2 指标体系

| 类别 | 指标 | 计算口径 |
|---|---|---|
| 北极星 | 平均审批时长 | `Σ(终审完成时间 - 提交时间) / 单据数` |
| 北极星 | 一次通过率 | `无退回且一次通过的单据数 / 提交单据数` |
| 效率 | 单据阅读时长 | 审批人打开单据到提交意见的时长 |
| 效率 | 节点停留时长 | `节点离开时间 - 节点进入时间` |
| 质量 | 建议采纳率 | `采纳（含部分采纳）的节点数 / 给出建议的节点数` |
| 质量 | 采纳后修改率 | 采纳后仍修改结论的节点数 / 采纳节点数 |
| 质量 | 风险准确率 | 人工确认为真的 AI 风险项 / AI 提出的风险项 |
| 质量 | 漏检率 | 人工发现但 AI 未发现的问题 / 人工发现问题总数 |
| 稳定性 | 降级率 | `超时/失败/低置信转人工次数 / 总请求数` |
| 稳定性 | 建议可用率 | `status=completed 且置信度达标的请求 / 总请求数` |
| 成本 | 单均成本 | `(模型费 + 检索费 + 算力) / 处理单据数` |
| 成本 | 缓存命中率 | 命中缓存的请求 / 总请求数 |
| 安全 | 越权与泄露事件 | 必须为 0 |
| 可追溯 | 证据覆盖率 | 带完整证据引用的结论数 / 结论总数 |

### 9.3 实验设计

| 项 | 方案 |
|---|---|
| 基线期 | 上线前一个完整审批周期，覆盖主要单据类型与部门 |
| 对照组 | 同期未启用 AI 的同类单据（优先同期对照，减少季节性偏差） |
| 灰度维度 | 租户 → 部门 → 单据类型 → 金额档位，逐层扩大 |
| 样本分层 | 单据类型 × 金额段 × 部门 × 审批节点 |
| 盲评 | 抽样单据由风控/审计独立复核 AI 风险项，评估准确率与漏检率 |
| 数据来源 | OA 流程事件、AI 请求日志、审计记录、人工决策结果、抽样复核结果 |
| 分析频率 | 每个灰度批次结束后复盘一次；异常立即回滚 |

### 9.4 建议验收门槛（POC 前按基线校准）

| 维度 | 参考门槛 |
|---|---|
| 建议采纳率 | ≥ 60%（按单据类型分别设定） |
| 风险准确率 | ≥ 80%；高风险项要求 ≥ 90% |
| 漏检率 | ≤ 5% 且无重大合规漏检 |
| 降级率 | ≤ 3% |
| 安全事件 | 越权/敏感泄露 = 0 |
| 证据覆盖率 | 100% 结论带证据引用 |
| 审批时长 | 对照组的下降幅度达到业务预设目标 |
| 单均成本 | 不超过单据类型预设预算上限 |

> 门槛值不是拍脑袋写死：POC 基线出来后，由业务、风控、财务共同签字确认。

### 9.5 埋点清单

| 事件 | 关键字段 |
|---|---|
| `bill_submitted` | `bill_id`、`bill_type`、`amount`、`department_id`、`tenant_id` |
| `ai_review_requested` | `review_mode`、`node_id`、`idempotency_key`、`trace_id` |
| `ai_review_completed` | `status`、`decision`、`confidence`、`latency_ms`、`versions` |
| `ai_review_degraded` | `reason`（timeout/quota/model/schema） |
| `ai_suggestion_viewed` | `review_id`、`viewer_id`、`node_id` |
| `approval_decided` | `decision`、`duration_ms`、`override_ai`（是否推翻建议） |
| `postcheck_finding` | `finding_code`、`confirmed`、`severity` |
| `cost_recorded` | `tokens`、`cost`、`model`、`tenant_id` |

### 9.6 失败案例复盘

每次灰度批次抽取以下样本：

1. AI 建议被推翻的单据（分析原因：数据缺失、规则冲突、模型误判）。
2. 人工发现但 AI 漏检的风险（补充规则或检索语料）。
3. 降级与超时请求（排查模型、配额、网络、附件解析）。
4. 高置信度但结论错误的样本（评估置信度标定是否有效）。

复盘结论进入 badcase 库，驱动提示词、规则集与知识库迭代。

## 10. 风险与回滚

| 风险 | 应对 |
|---|---|
| 审批人抵触 AI 建议 | 先只读旁路、可一键关闭；展示证据而非只给结论 |
| 模型误判造成业务损失 | AI 不自动放行；高风险单据强制人工复核 |
| 附件解析质量差 | 解析失败标为缺失项，不猜测内容 |
| 成本超预算 | 租户配额 + 单类型限流 + 结果缓存 + 小模型分流 |
| 上线后指标恶化 | 按租户/部门维度一键关闭 AI 节点，流程回退原路径 |
| 合规审计不通过 | 全链路版本号与证据引用，支持按 trace 回放 |

## 11. 实施阶段

| 阶段 | 内容 | 出关条件 |
|---|---|---|
| M0 基线测量 | 采集历史流程数据，确定指标口径与门槛 | 基线报告与验收表签字 |
| M1 只读 POC | 审批人助手 + 建议卡片，异步预审小流量灰度 | 建议采纳率、风险准确率达标；无安全事件 |
| M2 灰度扩展 | 扩大租户/部门/单据类型；接入会签汇总 | 效率指标稳定改善，成本在预算内 |
| M3 生产推广 | 归档质检、运营看板、配额计费、多实例部署 | 可对外承诺 SLA，具备回滚与审计能力 |

> 阶段之间设置硬门槛：**安全与合规不达标不进入下一阶段**。
